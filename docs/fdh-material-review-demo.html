1. Demo 要回答什么问题

目标不是替代 ImmD 正式审批，而是向客户展示 AI 应用层如何把材料包转成可审计的审核结论。

产品团队关注

办案人员先选申请类别，系统自动生成应交清单，提示缺件、错件、不适用件和补件建议，并能解释每个结论来自哪份材料。

技术团队关注

材料 taxonomy、字段 schema、规则引擎、证据 bbox、置信度和报告 JSON 必须可配置、可回归、可对接 APPLIES-2。

客户演示关注

上传一组模拟材料后，页面展示“可受理 / 需补件 / 需人工复核 / 明显不合规”四类结论，并高亮问题位置。

2. 建议 Demo 流程

首期可用静态样例材料跑通端到端，后续再接真实 OCR、局部重识别和报告 PDF 生成。

1选择申请类别入境签证、于两年合约期届满后续约、完成余下期间、转换雇主。
2生成应交清单读取 checklist tick、脚注、提交渠道和条件豁免。
3提交材料包模拟 PDF / 图片上传，识别模板、页数、版本和重复件。
4字段与规则核验抽取姓名、证件、地址、工资、签名等标准字段并跨文件比对。
5输出结论生成 Cross-Check Report、问题证据、JSON metadata 和 Minutes 草拟依据。

        5. 标准化字段与核查标准

        字段不是按文件孤立存储，而是按“傭工 / 雇主 / 合约 / 证明材料 / 文档元数据”形成统一 schema。

        案件与文档

        • 申请类别、提交渠道、caseId
        • documentType、templateId、footerId
        • pageCount、fileHash、qualityFlags
        • 来源页码、bbox、置信度、crop 证据

        傭工字段

        • 英文姓名、中文名、出生日期、国籍
        • 旅行证件号码、签发地、到期日
        • HKID 如适用、联系方式、近照
        • 工作经历、声明事项、签名

        雇主字段

        • 姓名、HKID / passport、出生日期
        • 住宅地址、通讯地址、联系方式
        • 收入声明、住户成员、现有傭工
        • 签名与声明日期

        合约字段

        • D.H. Contract No.、签约日期
        • 合约期、开始日期、雇主住址
        • 月薪、膳食或膳食津贴
        • 住宿安排、家务职责、双方签名

        6. 可模拟的异常场景

        演示时不需要一次展示所有规则，建议按客户最容易理解的缺件、错件、一致性、合规阈值四条线组织。

        文件分類类

        缺件、错件、不适用材料上传、重复上传、页数异常、模板版本错误、文件模糊、旋转、裁边、非中英文但缺翻译。

        字段完整性类

        ID 988A 未贴相片、ID 988A / ID 988B / ID 407 缺签名、合约编号缺失、日期缺失、住址证明无签发日期。

        跨文件一致性类

        傭工姓名与护照不一致、旅行证件号不一致、雇主证件号不一致、合约地址与地址证明不一致、住户人数不一致。

        业务规则类

        雇主收入低于 HK$15,000、合约工资低于当前 MAW、膳食津贴低于当前标准、地址证明超过 3 个月、护照有效期不足。

        7. 结论类型与报告输出

        结论必须可解释、可追溯、可导出，避免只给一个黑盒分数。

        结论含义产品动作
        PASS材料齐全，关键字段和业务规则未发现问题。可进入后续审批或生成 Minutes 草稿。
        WARN存在多余件、低风险提醒或可解释差异。报告提示，但不阻断。
        REVIEWOCR 置信度低、签名/印章模糊、规则需人工判断。推送人工复核队列并附证据 crop。
        FAIL缺必交材料、关键字段不一致或明显不符合规则。建议退回补件或标记不可受理。

        8. 首期实现建议

        先把规则做成配置和可回归样本，不要把申请类别、材料要求和字段阈值写死在代码里。

        配置 1：附件 taxonomy

        定义四类申请各自 required / conditional / waived / notApplicable 的材料规则，并记录官网脚注。

        配置 2：字段 schema

        定义字段 key、来源文件、页码锚点、标准化方式、必填条件、证据位置和置信度阈值。

        配置 3：核验规则集

        定义规则 ID、适用申请类别、严重性、判断逻辑、输出文案和是否进入人工复核队列。
