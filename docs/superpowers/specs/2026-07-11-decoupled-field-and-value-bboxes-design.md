# 字段与值 bbox 完全解耦设计

## 背景

当前字段证据链路会尝试通过 OCR 同时定位字段名和值，只有两者都定位成功时才生成裁判截图。手写值、复选框和 OCR 文本差异会导致值定位失败，使大量字段落入“裁判未完成”。这也混淆了两个不同目的：页面高亮需要准确的字段名位置，裁判模型需要填写值区域。

## 目标

- OCR 只根据 LLM 结构化识别结果中的字段名定位 `labelBbox`。
- LLM `_field_evidence` 中的原始 `value_bbox` 保留为 `valueBbox`。
- 前端页面高亮只使用 `labelBbox`。
- 裁判模型只接收从 `valueBbox` 裁剪的值区域图片，并在裁剪时增加少量安全边距。
- 裁判结果成功时展示识别值、匹配类型和评分；失败时展示明确原因，不再统一显示“裁判未完成”。

## 非目标

- 不让 OCR 重新识别或替换 LLM 的值 bbox。
- 不把字段名 bbox 与值 bbox 合并为裁判截图。
- 不调整 LLM 的结构化字段和值识别逻辑。
- 不改变现有字段通过、待复核等业务判定阈值。

## 数据模型

每个结构化字段保留以下独立坐标：

- `recognitionBbox`：LLM 原始值 bbox 的兼容字段。
- `valueBbox`：LLM 原始值 bbox，作为裁判截图的唯一定位来源。
- `labelBbox`：本地 OCR 根据字段名匹配得到的字段标签 bbox。
- `bbox`：面向前端高亮的公共坐标，值固定取 `labelBbox`；未可靠定位字段名时为空。

现有 `evidenceBbox` 可以继续作为兼容或诊断字段，但不得参与前端高亮和裁判截图选择。

## 数据流

1. LLM 输出页面结构化字段、字段显示名和值 bbox。
2. 后端解析 LLM 值 bbox，并同时赋给 `recognitionBbox` 与 `valueBbox`。
3. 本地 OCR 对整页印刷文字做检测，字段定位器只用字段显示名匹配 `labelBbox`。
4. 后端将 `bbox` 设置为可靠的 `labelBbox`，供前端绘制高亮。
5. 后端以 `valueBbox` 为中心生成裁判截图。截图可增加小幅安全边距，但不得扩展到 `labelBbox` 或使用两者并集。
6. 裁判模型独立读取截图中的填写值，与 LLM 结构化值比较，返回观察值、匹配类型、可读性和覆盖情况。
7. 评分器生成 `verificationScore` 与 `verificationStatus`，并通过组装层传递到前端。

## 安全边距

对外返回的 `valueBbox` 始终保持 LLM 原始坐标，不写回扩展后的坐标。仅在内存中生成裁判截图时增加少量水平和垂直边距，并将坐标限制在页面边界内。该规则用于减少字符边缘被截断的概率，同时保持字段和值坐标语义稳定。

## 状态与错误处理

- 裁判关闭：状态为 `not_run`，原因明确为 `judge_disabled`。
- LLM 值 bbox 缺失或非法：不调用裁判，原因明确为 `value_bbox_missing`。
- 裁剪失败：不调用裁判，原因明确为 `value_crop_failed`。
- 裁判接口不可用、超时或响应非法：保留对应原因码，不覆盖成笼统的未完成状态。
- 裁判成功：必须保留评分、观察值、匹配类型和具体说明。
- `shadow` 模式可保留评分数据，但不得因状态映射而让前端丢失评分。

前端在无评分时根据原因展示具体状态；只有仍在异步处理中时才使用“裁判未完成/等待中”的表达。

## 配置与凭据

裁判模型地址、模型名和 API key 只从本地环境或被 Git 忽略的 `llm.local.cmd` 读取。真实密钥不得写入源码、测试、设计文档、日志或提交记录。

## 测试策略

按测试驱动方式覆盖：

1. 当 OCR 找到字段名且 LLM 提供值 bbox 时，`bbox/labelBbox` 等于 OCR 字段 bbox，`valueBbox` 等于 LLM 原始 bbox。
2. 当 OCR 找不到值文本时，只要 LLM 值 bbox 有效，裁判仍会收到值区域截图。
3. 裁判截图来自带安全边距的 `valueBbox`，不包含或合并 `labelBbox`。
4. 前端高亮选择只读取 `labelBbox`，不能回退到 `valueBbox` 或 `evidenceBbox`。
5. 裁判成功结果完整传递到字段来源和文档字段展示。
6. 值 bbox 缺失、裁剪失败和裁判接口失败分别展示可区分的原因。
7. 运行 OCR sidecar、后端重点测试、前端单元测试和构建；条件允许时用现有 IANG 测试材料完成一次本地端到端验证。

## 验收标准

- 页面字段高亮框只覆盖 OCR 定位的字段名称。
- 裁判模型读取的是 LLM 值 bbox 对应的填写值区域。
- OCR 无法识别填写值不会阻止裁判执行。
- 有效裁判响应能够显示实际评分，不再全部显示“裁判未完成”。
- 无法评分的字段展示明确且可诊断的失败原因。
